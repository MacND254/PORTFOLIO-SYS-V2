# UPGRADE EXISTING CV/RESUME SCANNING SYSTEM — ACCURACY, EXTRACTION & PROFILE FIELD MATCHING

Act as a senior full-stack architect, AI/document-processing engineer, resume parsing specialist, data extraction engineer, debugging specialist, database engineer, and UX engineer.

The Portfolio SaaS already contains an existing **CV/Resume upload and scanning feature**.

The purpose of this task is **NOT to create a new CV scanner from scratch**.

The purpose is to:

> **AUDIT → DEBUG → RE-ENGINEER → UPGRADE the existing CV/Resume scanning and extraction system so that it extracts significantly more accurate information from real-world CVs and correctly maps that information to the existing Edit Profile fields.**

The current implementation has errors in data extraction and/or field matching.

Your job is to identify the root causes of those errors and substantially improve the existing implementation.

# PHASE 7 — SECTION DETECTION

Improve section recognition.

The scanner must recognize semantic equivalents.

For example:

```text
PROFESSIONAL EXPERIENCE
WORK EXPERIENCE
EMPLOYMENT HISTORY
CAREER HISTORY
PROFESSIONAL BACKGROUND
WORK HISTORY
```

should be recognized as the same conceptual section.

Likewise:

```text
EDUCATION
ACADEMIC BACKGROUND
EDUCATIONAL QUALIFICATIONS
ACADEMIC HISTORY
```

and:

```text
SKILLS
TECHNICAL SKILLS
CORE COMPETENCIES
AREAS OF EXPERTISE
TECHNICAL EXPERTISE
```

Do not rely only on exact heading matching.

Use contextual and semantic classification.

# PHASE 8 — CONTEXT-AWARE EXTRACTION

Do not extract information solely based on keywords.

The scanner must understand context.

Example:

```text
"Worked with JavaScript developers"
```

does NOT necessarily mean:

```text
Skill = JavaScript
```

unless the evidence supports that interpretation.

Similarly:

```text
"Managed a team of 8 engineers"
```

does not automatically mean:

```text
Skill = Engineering Management
```

unless appropriate.

Distinguish:

* Explicitly stated.
* Strongly supported by context.
* Weakly inferred.
* Unknown.

Do not turn weak inference into confirmed profile data.

# CORE OBJECTIVE

The objective is NOT:

> "Build a CV parser."

The objective is:

> **Upgrade the existing CV scanner so that it can reliably understand real-world CVs, accurately extract the information actually present in them, correctly associate related information, intelligently map that information to the existing Edit Profile fields, identify uncertainty/conflicts/duplicates, allow the user to verify and correct everything, and finally populate the existing profile without altering the existing Edit Profile module.**

The existing Edit Profile remains the **source of truth for what the portfolio accepts**.

The CV remains the **source of truth for what information the user has provided**.

The upgraded scanner is the **intelligent bridge between the two**.
